# WebParser与网络模块分析文档

## 1. 模块概述

xsmth-newsmth项目的核心技术之一是通过解析HTML内容直接获取数据，而不依赖API接口。这主要由两个关键模块实现：**jsParser**和**SMNetwork**。本文档详细分析这两个模块的工作原理、API及数据处理流程。

## 2. jsParser模块

jsParser模块是一个JavaScript解析引擎，负责将HTML内容解析为结构化的JSON数据。它利用JavaScript的DOM操作能力，通过CSS选择器提取网页中的特定内容。

```javascript
var parser = function(html) {

        };
```

```javascript
    }
```

```javascript
    if (pagination) {

                if (page > maxPage) {
                    maxPage = page;
                }
            }
            result.pagination.totalPages = maxPage;
        }
    }
    
    return result;
};
```

## 3. SMNetwork模块

### 3.1 基本原理

SMNetwork模块是Swift实现的网络请求封装层，负责与水木社区网站交互，获取HTML内容并调用解析器处理。该模块使用Alamofire作为底层网络库，提供了一系列针对水木社区各功能的API。

### 3.2 主要API及实现

#### 3.2.1 主页内容请求

```swift
static func fetchMainPage(completion: @escaping (Error?, SMMainPage?) -> Void) {
    let url = "https://www.newsmth.net/nForum/index"
    
    Alamofire.request(url, method: .get, headers: getCommonHeaders())
        .responseData { response in
            switch response.result {
            case .success(let data):
                if let html = String(data: data, encoding: .utf8) {
                    // 使用WebParser解析HTML
                    let script = SMWebParser.parserForType(.mainPage)
                    if let json = SMWebParser.parseHTML(html, withScript: script) as? [String: Any] {
                        // 转换为数据模型
                        let mainPage = SMMainPage.fromJSON(json)
                        completion(nil, mainPage)
                    } else {
                        let error = NSError(domain: SM_ERROR_DOMAIN, 
                                          code: SMNetworkErrorCodeParseFail.rawValue, 
                                          userInfo: nil)
                        completion(error, nil)
                    }
                }
            case .failure(let error):
                completion(error, nil)
            }
        }
}
```

```swift
private static func saveCookies(response: HTTPURLResponse?) {
    guard let response = response,
          let headerFields = response.allHeaderFields as? [String: String],
          let url = response.url else { return }
    
    let cookies = HTTPCookie.cookies(withResponseHeaderFields: headerFields, for: url)
    
    // 保存到用户偏好
    var cookieDict = [[HTTPCookiePropertyKey: Any]]()
    for cookie in cookies {
        var cookieProperties = [HTTPCookiePropertyKey: Any]()
        cookieProperties[.name] = cookie.name
        cookieProperties[.value] = cookie.value
        cookieProperties[.domain] = cookie.domain
        cookieProperties[.path] = cookie.path
        cookieProperties[.version] = cookie.version
        cookieProperties[.expires] = cookie.expiresDate
        
        cookieDict.append(cookieProperties)
    }
    
    UserDefaults.standard.set(cookieDict, forKey: USERDEFAULTS_COOKIES)
    UserDefaults.standard.synchronize()
}

private static func loadCookies() {
    guard let cookieDict = UserDefaults.standard.array(forKey: USERDEFAULTS_COOKIES) as? [[HTTPCookiePropertyKey: Any]] else { return }
    
    for cookieProperties in cookieDict {
        if let cookie = HTTPCookie(properties: cookieProperties) {
            HTTPCookieStorage.shared.setCookie(cookie)
        }
    }
}
```

## 4. SMWebParser模块

### 4.1 基本原理

SMWebParser是连接网络层和解析脚本的桥梁，负责加载和执行JavaScript解析脚本，将HTML内容转换为JSON数据。

### 4.2 主要API及实现

```objc
// 解析HTML为JSON
+ (id)parseHTML:(NSString *)html withScript:(NSString *)script {
    JSContext *context = [[JSContext alloc] init];
    
    // 设置异常处理
    [context setExceptionHandler:^(JSContext *ctx, JSValue *exception) {
        NSLog(@"JS Exception: %@", exception);
    }];
    
    // 执行解析脚本
    [context evaluateScript:script];
    JSValue *parserFunction = context[@"parser"];
    
    if ([parserFunction isUndefined] || [parserFunction isNull]) {
        return nil;
    }
    
    // 调用解析函数
    JSValue *result = [parserFunction callWithArguments:@[html]];
    return [result toObject];
}

// 获取指定类型的解析脚本
+ (NSString *)parserForType:(SMWebParserType)type {
    NSString *fileName;
    
    switch (type) {
        case SMWebParserTypeMainPage:
            fileName = @"main_page_parser.js";
            break;
        case SMWebParserTypeBoardList:
            fileName = @"board_list_parser.js";
            break;
        case SMWebParserTypePostList:
            fileName = @"post_list_parser.js";
            break;
        case SMWebParserTypePostContent:
            fileName = @"post_content_parser.js";
            break;
        case SMWebParserTypeLoginResult:
            fileName = @"login_result_parser.js";
            break;
        // 其他类型...
        default:
            return nil;
    }
    
    // 先尝试从缓存读取
    NSString *cachedScript = [self cachedScriptForFile:fileName];
    if (cachedScript) {
        return cachedScript;
    }
    
    // 从本地加载
    NSString *path = [[NSBundle mainBundle] pathForResource:[fileName stringByDeletingPathExtension] 
                                                    ofType:[fileName pathExtension]
                                               inDirectory:@"jsParser"];
    
    if (path) {
        NSError *error;
        NSString *script = [NSString stringWithContentsOfFile:path encoding:NSUTF8StringEncoding error:&error];
        if (!error) {
            return script;
        }
    }
    
    return nil;
}

// 动态更新解析脚本
+ (void)updateParsers {
    // 从服务器获取最新脚本列表
    [SMHttpRequest requestWithURL:@"https://your-server.com/parsers/list"]
    .startWithCompletionHandler:^(NSData *data, NSError *error) {
        if (error) {
            return;
        }
        
        NSError *jsonError;
        NSDictionary *parsers = [NSJSONSerialization JSONObjectWithData:data
                                                                options:0
                                                                  error:&jsonError];
        if (jsonError) {
            return;
        }
        
        // 检查需要更新的脚本
        for (NSString *parserName in parsers) {
            NSString *version = parsers[parserName][@"version"];
            NSString *localVersion = [self localVersionForParser:parserName];
            
            if (![version isEqualToString:localVersion]) {
                // 下载新版本脚本
                [self downloadParser:parserName version:version];
            }
        }
    }];
}
```

## 5. 数据流程总结

### 5.1 完整处理流程

1. **用户界面触发请求**
   - 用户点击版块、帖子等UI元素
   - 视图控制器调用对应的网络请求方法

2. **网络层发送请求**
   - SMNetwork构建请求
   - Alamofire执行HTTP请求
   - 获取HTML响应内容

3. **解析引擎处理HTML**
   - SMWebParser加载解析脚本
   - 执行JavaScript解析逻辑
   - 使用DOM选择器提取数据
   - 返回结构化JSON数据

4. **数据模型转换**
   - 将JSON转换为对应的数据模型类实例
   - 处理数据格式转换和类型映射

5. **UI绑定与展示**
   - 视图控制器接收数据模型
   - 更新UI组件显示内容
   - 处理用户交互事件

### 5.2 示例：从请求到UI展示

## 6. 技术优势与挑战

### 6.1 技术优势

1. **灵活性**：通过更新解析脚本，可以适应网站HTML结构的变化，无需更新整个应用
2. **独立性**：无需依赖后端API，可直接与网站交互
3. **动态性**：解析脚本可以动态更新，实现热修复
4. **开发效率**：使用DOM操作和CSS选择器，比正则表达式更直观和高效

### 6.2 技术挑战

1. **稳定性**：网站HTML结构变更可能导致解析失败
2. **性能开销**：JavaScript解析可能导致性能开销
3. **维护复杂性**：需要维护多个解析脚本，增加复杂性
4. **调试难度**：跨语言调试（Objective-C/Swift与JavaScript）有一定难度

## 7. 最佳实践

1. **解析脚本测试**：为每个解析脚本编写测试用例，确保解析准确性
2. **容错处理**：解析逻辑中添加充分的错误处理和默认值
3. **版本控制**：对解析脚本进行版本控制，便于回滚和更新
4. **缓存策略**：实现有效的缓存策略，减少重复解析
5. **监控机制**：添加解析失败监控，及时发现和修复问题

## 8. 结论

jsParser和SMNetwork模块共同构成了xsmth-newsmth项目的核心数据获取机制。这种基于HTML解析的方式为应用提供了极大的灵活性和独立性，是项目的一大特色。虽然这种方式有一定的复杂性和挑战，但通过良好的设计和实践，可以有效地克服这些问题，实现可靠、高效的数据获取和处理。

#### **一、 整体流程概述**

该登录功能的核心是利用一个 `WKWebView` 来加载水木社区（newsmth.net）的手机版登录页面。用户在网页上完成登录操作（包括输入账号密码和通过真人验证）后，iOS App 会从 `WKWebView` 中监听并提取登录成功后服务器设置的 `Cookie`，并将其保存到 App 的全局网络请求模块中，从而实现用户的登录状态。整个过程对用户来说，就像是在一个应用内浏览器中完成了登录。

**核心流程图:**

```mermaid
graph TD
    A[启动登录页面 SMLoginViewControllerV2] --> B{创建并配置 WKWebView};
    B --> C[加载登录URL<br>https://m.newsmth.net/index];
    C --> D{页面加载完成<br>webView:didFinish};
    D --> E[注入JavaScript脚本<br>以优化页面显示、预填用户名密码];
    E --> F[用户在网页中输入凭据并<br>完成真人验证后点击登录];
    F --> G{网页触发表单提交/页面跳转};
    G --> H{App拦截跳转请求<br>webView:decidePolicyFor};
    H --> I[从WebView中读取所有Cookie];
    I --> J{筛选出关键的登录Cookie<br>(main[UTMP*])};
    J --> K[将登录Cookie保存到<br>全局的HTTPCookieStorage和SMAccountManager];
    K --> L{SMAccountManager<br>确认登录状态};
    L -- 登录成功 --> M[调用loginSuccess方法];
    M --> N[关闭登录页面并执行成功回调];
    L -- 登录未成功 --> O[继续WebView流程];
```

#### **二、 详细实现分析**

**1. WebView 的初始化与配置 (`viewDidLoad`)**

-   **控制器**: `SMLoginViewControllerV2` 继承自一个名为 `XWebController` 的基类，它内部封装了 `WKWebView`。
-   **内容拦截规则 (Content Blocker)**:
    -   为了提升加载速度和屏蔽追踪，代码定义了一套 `WKContentRuleList` 规则。
    -   规则以 JSON 字符串形式定义，主要作用是 **拦截并阻止加载** 来自 `google.*` 和 `hm.baidu.*` 的脚本资源。
    -   通过 `WKContentRuleListStore.default().compileContentRuleList` 编译并应用到 `WKWebView` 的 `configuration` 中。
-   **加载初始页面**:
    -   在内容拦截规则配置成功后的回调里，WebView 开始加载 `https://m.newsmth.net/index`。

**2. 页面加载完成后的交互 (`webView:didFinish:`)**

当 `WebView` 完成页面加载后，App 会通过 `evaluateJavaScript` 方法向页面注入一段 JS 脚本，用于改善用户体验和实现特定功能。

-   **JS 脚本主要功能**:
    -   **DOM 元素隐藏 (已注释)**: 代码中预留了隐藏广告容器 (`#ad_container`)、logo、菜单等元素的逻辑，但当前被注释掉了。
    -   **调整样式**: 放大登录表单区域 (`#u_login`) 的字体，方便用户输入。
    -   **自动填充**:
        -   从 `window.localStorage` 中读取键为 `_xsmth_userinfo` 的数据。
        -   如果存在，则解析出 `id` 和 `passwd` 并自动填充到对应的输入框中。
    -   **保存用户输入**:
        -   监听真人验证按钮 (`#TencentCaptcha`) 的点击事件。
        -   当用户点击该按钮时，将当前输入框中的 `id` 和 `passwd` 保存到 `window.localStorage` 中，键依然是 `_xsmth_userinfo`。这确保了下次登录时可以自动填充。
    -   **强制登录 (可选)**: 如果 `SMConfig.enableForceLogin()` 为 `true`，脚本会自动点击真人验证按钮，可能用于实现某种程度的自动登录。
    -   **主题适配**: 将网页的文字颜色设置为与 App 主题色一致。

**3. 导航拦截与 Cookie 获取 (`webView:decidePolicyFor:decisionHandler:`)**

这是实现登录状态捕获的核心所在。该方法会在 `WebView` 的每一次页面跳转前被调用。

-   **逻辑判断**:
    -   首先，代码会判断请求的 `URL host` 是否为 `m.newsmth.net`。登录成功后的跳转通常仍在此域名下。
    -   如果是，则执行 Cookie 获取逻辑。
-   **Cookie 获取与处理**:
    1.  通过 `self.webView.configuration.websiteDataStore.httpCookieStore.getAllCookies` 异步获取当前 `WebView` 中的所有 `Cookie`。
    2.  遍历 `Cookie` 列表，筛选出对我们有用的登录凭证。
    3.  **筛选条件**:
        -   `domain` 必须是 `.newsmth.net`。
        -   `name` 必须是以下三者之一：`main[UTMPNUM]`, `main[UTMPKEY]`, `main[UTMPUSERID]`。这三个是水木社区用来标识用户登录状态的核心 `Cookie`。
    4.  **Cookie 持久化**:
        -   对于筛选出的登录 `Cookie`，代码会重新创建一个 `HTTPCookie` 对象，并设置一个较长的过期时间（至少7天），然后通过 `HTTPCookieStorage.shared.setCookie(c!)` 将其存入 App 的全局 `Cookie` 存储区。
        -   **关键点**: 存入 `HTTPCookieStorage` 后，App 内所有使用标准网络库（如 `URLSession`）发起的对 `newsmth.net` 的请求，都会自动带上这些 `Cookie`，从而实现了 App 的 "登录状态"。
-   **确认登录状态**:
    -   在处理完 `Cookie` 后，代码会调用 `SMAccountManager.instance()?.setCookies(cookies)`，让账户管理单例类也拿到这些 `Cookie`。
    -   接着检查 `SMAccountManager.instance()?.isLogin`。这个 `isLogin` 属性的 `true/false` 就是判断登录是否成功的最终依据（其内部逻辑很可能是检查是否存在上述三个关键 `Cookie`）。
    -   如果 `isLogin` 为 `true`，则调用 `self?.loginSuccess()`。

**4. 登录成功处理 (`loginSuccess`)**

-   当确认登录成功后，此方法被调用。
-   它会执行外部传入的成功回调 (`successFunc` 或 `target`/`selector`)。
-   最后，关闭当前的登录视图控制器 `self.close()`，流程结束。

#### **三、 Flutter 实现建议**

基于以上分析，在 Flutter 中使用 `flutter_inappwebview` 或 `webview_flutter` 插件实现此功能时，可以遵循以下步骤：

1.  **WebView 创建**:
    -   创建一个 `InAppWebView` (推荐 `flutter_inappwebview`，功能更强大)。
    -   加载 URL: `https://m.newsmth.net/index`。
    -   **内容拦截**: `flutter_inappwebview` 支持 `ContentBlocker`。你可以同样地创建规则来屏蔽 Google 和百度的 JS，以提升性能。

2.  **JS 注入 (`onLoadStop`)**:
    -   在 `onLoadStop` (或 `onPageFinished`) 回调中，使用 `controller.evaluateJavascript()` 方法注入与原生 App 中类似的 JS 脚本。
    -   你需要复现 JS 脚本中的所有逻辑：放大字体、从本地存储（可以使用 `shared_preferences` 结合 JS 来实现）读取/写入用户信息。

3.  **Cookie 监听与提取**:
    -   这是最关键的一步。你需要一个机制来获取 `WebView` 中的 `Cookie`。
    -   **推荐方案**: 使用 `flutter_inappwebview` 的 `CookieManager`。在 `onLoadStart` 或 `onUpdateVisitedHistory` (当URL变化时触发) 回调中，监听 `url` 的变化。
        ```dart
        // InAppWebView onUpdateVisitedHistory callback
        onUpdateVisitedHistory: (controller, url, androidIsReload) async {
          if (url != null && url.host == "m.newsmth.net") {
            // It's better to use getCookies for the specific domain
            final cookies = await CookieManager.instance().getCookies(url: WebUri("https://m.newsmth.net"));
            // ... process cookies
          }
        }
        ```

4.  **Cookie 处理**:
    -   获取到 `Cookie` 列表后，在 Dart 代码中进行遍历和筛选。
    -   找出 `domain` 为 `.newsmth.net` 且 `name` 为 `main[UTMPNUM]`、`main[UTMPKEY]` 或 `main[UTMPUSERID]` 的 `Cookie`。
    -   **持久化 Cookie**: 将这些重要的 `Cookie` 保存起来。
        -   **推荐做法**: 使用 `dio_cookie_manager` 配合 `dio` 网络库。将提取到的 `Cookie` 添加到 `CookieJar` 中。这样，之后所有通过 `dio` 发起的网络请求就都会自动携带登录凭证。
        -   如果不使用 `dio`，也需要将 `Cookie` 字符串保存到 `shared_preferences`，并在构造网络请求时手动添加到 `Header` 中。

5.  **判断登录成功与流程控制**:
    -   当成功提取并保存了上述三个关键 `Cookie` 后，就可以认为登录成功。
    -   在 Dart 代码中管理一个登录状态（例如，使用 `Provider`, `Bloc` 或 `Riverpod` 等状态管理工具）。
    -   关闭 `WebView` 页面（`Navigator.pop(context)`），并通知 App 的其他部分更新UI，显示为已登录状态。

**总结**: 核心思想是 **"WebView 充当登录媒介，App 充当 Cookie 搬运工"**。只要能准确地复现 JS 注入逻辑，并可靠地从 `WebView` 中捕获和持久化关键 `Cookie`，就能在 Flutter 上成功复刻此功能。
